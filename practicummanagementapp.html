Practicum Management App

A production-ready internal platform built for Vancouver Island University's ITAS department to manage student practicum placements, employers, and opportunities. I inherited a functional but rough application and led the UI overhaul, QA testing, and production readiness documentation — working directly with the VIU department as the client.

Role

UI Overhaul, QA & Documentation

Context

Solo Practicum Placement

Course

ITAS 195T — Practicum

Client

VIU ITAS Department

The Problem

A working app with a broken user experience

The Practicum Management App had been built by a previous team of students — the backend logic was largely in place, but the user interface was inconsistent, confusing, and not ready for real instructors to use. Forms created incomplete database records, validation errors gave no useful feedback, confirmation dialogs were basic browser alerts, and several core workflows were broken or missing entirely.

My job was to take this app from "it mostly works" to genuinely production ready — fixing the UI across every page, documenting every feature and bug, and communicating clearly with the department about what was done, what was outstanding, and what decisions still needed to be made.

What I Delivered

Five pages brought to production standard

I audited every page of the application, documented all bugs and UX issues, then rebuilt the frontend workflows one by one — replacing broken patterns with professional, consistent interactions throughout.

Students Page

Replaced broken inline creation with a modal-based workflow. Added real-time form validation, duplicate email prevention, pagination, and professional confirmation dialogs for delete operations.

Employers Page

Rebuilt employer creation to stop incomplete records being saved to the database. Added cascading contact and address management, phone and postal code validation, and inline editing for all fields.

Opportunities Page

Replaced confusing search-based employer selection with searchable dropdowns. Added cascading logic where employer selection auto-populates contacts and addresses, plus proper date range selection.

Placements Page

Fixed student assignment persistence, added unassign functionality, rebuilt the matching system to prevent double-booking, and added comprehensive search across students, employers, and placement details.

Home Dashboard

Replaced a confusing data-heavy landing page with a clear onboarding overview designed for new instructors — feature descriptions, workflow steps, and direct navigation to each section.

Testing & Documentation

Produced a comprehensive production readiness document covering every user story, feature status, bug history, improvements made, outstanding items, and open questions for the client — across all user roles.

The Process

Audit, document, fix, repeat

My process for each page was consistent: audit the existing state, document every issue with screenshots and notes, implement the fixes, then write up what was done, what improved, and what still needed decisions from the client. This gave the department a clear paper trail of where the app was and where it was going.

I tracked all issues through GitHub Projects using a Kanban board, which kept the backlog visible and allowed the client to see progress in real time. Meeting minutes and client emails were maintained throughout to ensure nothing was lost between sessions.

The final deliverable included not just working code but a full production readiness document — categorizing every feature as production ready, partially implemented, or not yet started — along with a development roadmap for whoever would pick this project up next.

Reflection

What it takes to make software actually ready

This project taught me that "it works" and "it's ready" are very different things. An app can pass basic functionality tests and still fail real users completely — because the error messages are unclear, the workflows are confusing, or the data doesn't actually save correctly under certain conditions.

Writing the production readiness documentation was as valuable as the code changes. Categorizing every feature, being honest about what was incomplete, and framing outstanding items as clear questions for the client — that kind of communication is what separates a student project from something an institution can actually depend on.

Working solo on a practicum placement also meant I had to manage my own time, prioritize what to fix first, and make judgment calls without a team to consult. That independence pushed me to think more like a professional and less like a student.
